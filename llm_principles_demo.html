1. 演进历程：RNN → Attention → Transformer

语言模型的三次飞跃

2013 — Word2Vec
词向量革命
将每个词映射为固定维度的向量，King - Man + Woman ≈ Queen。但无法处理一词多义（"bank" 是银行还是河岸？）
2014-2017 — RNN / LSTM / GRU
序列建模时代
一个词一个词地顺序处理，通过"隐藏状态"传递上下文。致命缺陷：长距离依赖遗忘 + 无法并行计算。
2015-2017 — Attention 机制
注意力增强 RNN
为 RNN 加了一双"回看全局"的眼睛，但底层仍是串行的 RNN。Seq2Seq + Attention 成为机器翻译标配。
2017 — Transformer
🔥 Attention Is All You Need
完全抛弃 RNN，纯注意力架构。所有位置可以并行计算，长距离依赖通过一步矩阵乘法直达。GPU 利用率飙升，催生 BERT、GPT 系列。
2018-Now — 大模型时代
BERT → GPT-2 → GPT-3 → GPT-4 → ...
参数从亿级到万亿级，涌现 In-Context Learning、Chain-of-Thought 等能力。Scaling Law 证明：更大 = 更强。

为什么 Transformer 能取代 RNN？

维度RNN / LSTMTransformer
计算方式串行逐词处理全并行 矩阵运算
长距离依赖信息衰减，越远越弱一步直达，任意位置
训练速度慢（无法并行）快（GPU 友好）
可扩展性难以超过 1B 参数轻松扩展到万亿级
位置信息天然有序需要额外的位置编码

2. LLM 整体架构：三大组件

从输入到输出的完整链路

一个 LLM 本质上由三部分组成：

🔤 Tokenizer
文本 → Token IDs
→
📐 Embedding
IDs → 向量
→
🧱 Transformer Blocks ×N
理解 & 推理
→
🎯 LM Head
向量 → 概率
→
📝 Decode
Token → 文本

🔤 Tokenizer — 分词器

将自然语言文本切分成子词 Token，再映射为整数 ID。

"I love AI" → ["I", " love", " AI"] → [40, 3021, 9552] 常见算法: BPE (GPT), WordPiece (BERT), SentencePiece (LLaMA) 词表大小: 通常 32K ~ 150K

📐 Embedding — 嵌入层

将每个 Token ID 查表转换为高维向量，并加上位置编码。

Token ID: 40 → 查 Embedding Table → [0.12, -0.34, 0.78, ...] (4096维) 位置编码: 告诉模型每个 Token 在句子中的位置 - 绝对位置编码 (原始 Transformer) - RoPE 旋转位置编码 (LLaMA, GPT-NeoX) ← 主流

🧱 Transformer Blocks — 核心推理引擎

N 层相同结构的 Block 堆叠，每层包含 Self-Attention + FFN。

┌─────────────────────────────┐ │ Transformer Block │ │ │ │ Input → LayerNorm │ │ → Self-Attention │ ← 理解词与词的关系 │ → Residual Connection │ │ → LayerNorm │ │ → FFN (Feed-Forward) │ ← 存储知识 & 非线性变换 │ → Residual Connection │ │ → Output │ └─────────────────────────────┘ ↓ × N 层 (32~128层) LLaMA-2 7B: 32层 | GPT-4: 推测 120层+

🎯 LM Head — 语言模型头

将最后一层输出的向量映射回词表大小的概率分布。

隐藏向量 [4096维] → 线性层 [4096 × 词表大小] → Softmax → 概率分布 例如 (词表=32000): "the" → 0.35 ← 最高概率，被选中 "a" → 0.12 "this" → 0.08 ... 采样策略: Greedy / Top-K / Top-P (Nucleus) / Temperature

📝 Decode — 解码输出

将预测的 Token ID 转回文本，自回归地逐个生成。

自回归生成 (Autoregressive Generation): Step 1: "I love" → 预测 "AI" Step 2: "I love AI" → 预测 " and" Step 3: "I love AI and" → 预测 " machine" ... 每步把新预测的 Token 追加到输入序列，循环直到生成 <EOS> 或达到最大长度。

3. Tokenizer 分词器详解

BPE (Byte Pair Encoding) 算法

GPT 系列使用的分词算法，核心思想：从字符级开始，反复合并最高频的相邻对。

训练过程 (简化): Step 0: 初始词表 = 所有单个字节 (256个) Step 1: 统计所有相邻字节对出现频率 Step 2: 合并频率最高的对 → 新 Token Step 3: 重复直到词表大小达到目标 示例: "low low low lower" → 初始: [l, o, w, ' ', l, o, w, ' ', l, o, w, ' ', l, o, w, e, r] → 合并 (l,o) → lo: [lo, w, ' ', lo, w, ' ', lo, w, ' ', lo, w, e, r] → 合并 (lo,w) → low: [low, ' ', low, ' ', low, ' ', low, e, r] → ...
Tokenizer使用模型词表大小特点
BPEGPT-2/3/4, LLaMA32K~100K基于频率的子词合并
WordPieceBERT30K基于似然度的合并
SentencePieceT5, LLaMA32K语言无关，直接处理原始文本

4. Transformer Block 内部结构

每个 Block 的两大核心

┌──────────────────────────┐ │ 输入向量 (hidden) │ └────────────┬───────────────┘ │ ┌────────────▼───────────────┐ │ Layer Norm │ └────────────┬───────────────┘ │ ┌────────────────────────▼──────────────────────────┐ │ Self-Attention (多头注意力) │ │ "我该关注输入中的哪些词？" — 负责理解词间关系 │ └────────────────────────┬──────────────────────────┘ │ ┌───────▼───────┐ │ + 残差连接 │ ← 防止梯度消失 └───────┬───────┘ │ ┌────────────▼───────────────┐ │ Layer Norm │ └────────────┬───────────────┘ │ ┌────────────────────────▼──────────────────────────┐ │ FFN (前馈神经网络) │ │ "基于已理解的关系，进行深层推理" — 存储世界知识 │ └────────────────────────┬──────────────────────────┘ │ ┌───────▼───────┐ │ + 残差连接 │ └───────┬───────┘ │ ┌────────────▼───────────────┐ │ 输出向量 │ └──────────────────────────────┘

Self-Attention 类比：在教室里，每个学生（Token）环顾四周，决定关注哪些同学（其他 Token），从而理解完整语境。

FFN 类比：每个学生独立思考，从自己的"知识库"中检索和组合信息。FFN 的参数量占模型总参数的约 2/3！

残差连接 (Residual Connection) 的作用

x ─────────────────────────┐ │ │ ▼ │ ┌─────────────┐ │ │ Sub-Layer │ │ (跳跃连接) │ (Attention │ │ │ or FFN) │ │ └──────┬──────┘ │ │ │ ▼ │ output = SubLayer(x) + x ◄┘ 作用: 梯度可以"绕过"子层直接回传，深层网络 (100+层) 也能稳定训练。

5. Self-Attention 自注意力机制

Q / K / V 三兄弟

每个 Token 的向量通过三个不同的权重矩阵，分别变换出 Query、Key 和 Value。

输入向量 x (4096维) │ ├── × W_Q → Q (Query) "我在找什么？" — 好比你手里的搜索词 │ ├── × W_K → K (Key) "我能提供什么？" — 好比文档的关键词/标签 │ └── × W_V → V (Value) "我的实际内容" — 好比文档的正文内容 Attention(Q, K, V) = Softmax(Q × K^T / √d_k) × V ───────────────────────── 注意力权重矩阵

计算步骤可视化

Step 1: Q × K^T — 计算每对 Token 之间的相似度 ┌──────────────────────────────────────┐ │ "The cat sat on the mat" │ │ │ │ The cat sat on the mat│ │ The [0.8 0.2 0.1 0.0 0.7 0.1]│ │ cat [0.1 0.9 0.3 0.1 0.1 0.2]│ │ sat [0.2 0.4 0.8 0.3 0.1 0.1]│ │ on [0.1 0.1 0.2 0.7 0.3 0.5]│ │ the [0.6 0.1 0.1 0.3 0.8 0.4]│ │ mat [0.1 0.2 0.1 0.4 0.3 0.9]│ └──────────────────────────────────────┘ Step 2: / √d_k — 缩放，防止数值过大导致 Softmax 梯度消失 Step 3: Softmax — 归一化为概率分布（每行加起来=1） Step 4: × V — 用权重对 Value 加权求和，得到新的表示

Causal Mask（因果掩码）— GPT 的秘密

在 Decoder-only 模型中，每个 Token 只能看到它前面的 Token，不能偷看未来。这通过一个下三角掩码实现：

掩码矩阵 (1=可见, 0=遮挡): The cat sat on The [ 1 0 0 0 ] ← The 只能看自己 cat [ 1 1 0 0 ] ← cat 能看 The 和自己 sat [ 1 1 1 0 ] ← sat 能看前面3个词 on [ 1 1 1 1 ] ← on 能看所有前面的词 被遮挡的位置: score 设为 -∞ → Softmax 后 → 0

6. 多头注意力 & 优化变体

Multi-Head Attention (MHA)

一个注意力头只能捕获一种关系。多头注意力让模型同时从多个角度理解文本。

输入向量 (d_model = 4096) │ ┌─────────────────┼─────────────────┐ │ │ │ ┌───▼───┐ ┌───▼───┐ ┌───▼───┐ │ Head 1 │ │ Head 2 │ ... │Head 32│ │Q₁,K₁,V₁│ │Q₂,K₂,V₂│ │Q₃₂,K₃₂,V₃₂│ │128维 │ │128维 │ │128维 │ └───┬───┘ └───┬───┘ └───┬───┘ │ │ │ └────────┬────────┘─────────────────┘ │ Concatenate (拼接) ▼ ┌──────────────┐ │ W_O 线性投影 │ (32×128 = 4096 → 4096) └──────┬───────┘ ▼ 最终输出 (4096维) Head i 负责关注不同类型的关系: Head 1: 语法关系 (主谓宾) Head 5: 指代消解 ("it" 指向谁) Head 12: 位置邻近信息 Head 28: 语义相似度

MHA 的效率挑战 & 优化方案

Multi-Head Attention 标准方案

每个头有独立的 Q, K, V: Head 1: Q₁ K₁ V₁ (每组 128维) Head 2: Q₂ K₂ V₂ ... Head 32: Q₃₂ K₃₂ V₃₂ KV Cache 总量 = 32 头 × 2(K+V) × 序列长度 × 128维 → 长序列时内存爆炸！

问题：推理时每个头都要缓存 K 和 V，32 头 × 2 = 64 份缓存，内存占用极高。

Multi-Query Attention Google 2019

所有头共享同一份 K 和 V，只有 Q 是独立的: Head 1: Q₁ ─┐ Head 2: Q₂ ─┤──→ 共享 K, V ... │ Head 32: Q₃₂─┘ KV Cache 总量 = 1 × 2(K+V) × 序列长度 × 128维 → 内存降为 1/32！

优点：内存大幅下降，推理速度提升。

代价：质量略有下降，因为所有头看到相同的 K/V。

Grouped-Query Attention LLaMA 2 使用

折中方案：将 32 个头分成 8 组，每组共享 K/V: Group 1: Head 1-4 → 共享 K₁, V₁ Group 2: Head 5-8 → 共享 K₂, V₂ ... Group 8: Head 29-32 → 共享 K₈, V₈ KV Cache 总量 = 8 × 2(K+V) × 序列长度 × 128维 → 内存降为 1/4，质量接近 MHA！

GQA 是 MHA 和 MQA 的折中，被 LLaMA 2, Mistral, Gemma 等广泛采用。

Sparse Attention 稀疏注意力

标准 Attention: O(n²) — 每个 Token 看所有其他 Token Sparse Attention: 只看"重要"的一部分 ┌───────────────────────────┐ │ ■ ■ ■ □ □ □ □ □ □ ■ │ ← 局部窗口 + 全局锚点 │ ■ ■ ■ ■ □ □ □ □ □ ■ │ │ □ ■ ■ ■ ■ □ □ □ □ ■ │ ■ = 可见 │ □ □ ■ ■ ■ ■ □ □ □ ■ │ □ = 跳过 │ □ □ □ ■ ■ ■ ■ □ □ ■ │ │ ■ ■ ■ ■ ■ ■ ■ ■ ■ ■ │ ← 全局 Token └───────────────────────────┘ 代表模型: Longformer, BigBird, GPT-4(推测使用某种稀疏)

将复杂度从 O(n²) 降到 O(n√n) 或 O(n log n)，使超长序列（100K+ Token）成为可能。

7. FFN 前馈神经网络

为什么要"先膨胀再压缩"？

FFN 是 Transformer 中参数最多的部分（约占 2/3），其结构看似简单，实则是模型的"知识库"。

输入 x (4096维) │ ▼ ┌─────────┐ │ W_gate │──→ gate = σ(x · W_gate) 门控信号 └─────────┘ × ┌─────────┐ │ W_up │──→ up = SiLU(x · W_up) 升维: 4096 → 14336 (×3.5) └─────────┘ │ │ gate * up 逐元素相乘 │ ┌─────────┐ │ W_down │──→ output = (gate * up) · W_down 降维: 14336 → 4096 └─────────┘ │ ▼ 输出 (4096维)

维度膨胀的直觉

低维空间 (4096维)

所有概念被挤在一起，像一个拥挤的房间。"银行"和"河岸"的向量可能重叠。

高维空间 (14336维)

展开到更大的空间，每个概念有充足的"私人空间"来分开。在这里做非线性变换，精细地组合特征。

回到低维 (4096维)

提取最有用的信息压回标准维度，传给下一层。类似"升高分辨率 → 精修细节 → 压缩回正常尺寸"。

参数量计算

LLaMA 2 7B 的 FFN (SwiGLU 结构): W_gate: 4096 × 14336 = 58,720,256 W_up: 4096 × 14336 = 58,720,256 W_down: 14336 × 4096 = 58,720,256 ──────────────────────────────── 每层 FFN 参数: ~176M 32层 × 176M = 5.6B（FFN 总参数） 模型总参数: 7B FFN 占比: 5.6/7 ≈ 80%！

8. KV Cache 推理加速

为什么需要 KV Cache？

LLM 自回归生成时，每一步都要计算 Attention。如果重复计算所有 Token 的 K/V，浪费巨大。

1

输入 "I love"

计算 "I" 和 "love" 的 Q、K、V，将 K₁、V₁、K₂、V₂ 存入缓存。

2

生成第3个词

只计算新 Token 的 Q₃、K₃、V₃。K₃ 和 V₃ 追加到缓存。
用 Q₃ 跟 [K₁, K₂, K₃] 做注意力 → 不需要重新算 K₁、K₂！

3

生成第4个词

只算 Q₄、K₄、V₄。缓存中已有 [K₁,K₂,K₃]，追加 K₄ 即可。
复杂度从 O(n²) 降到 O(n)！

没有 KV Cache: 有 KV Cache: 生成第 n 个词时 生成第 n 个词时 → 重算所有 n 个 Token 的 K,V → 只算第 n 个 Token 的 K,V → O(n²) 总计算量 → O(n) 总计算量 → KV Cache 追加新的 K,V 代价: 内存占用增大 (需要存所有历史 K,V) LLaMA 7B, 序列长度 4096: = 32层 × 32头 × 2(K+V) × 4096 × 128维 × 2字节(FP16) ≈ 2 GB 显存只用于 KV Cache！

9. Encoder vs Decoder 架构对比

三种 Transformer 架构

Encoder-Only

双向注意力

[CLS] I love AI [SEP] ↕ ↕ ↕ ↕ ↕ 每个词都能看到所有词 代表: BERT, RoBERTa 擅长: 分类, NER, 问答 不擅长: 生成文本

Decoder-Only

因果掩码(单向)

I → love → AI → ? ← ← ← 每个词只能看前面的词 代表: GPT系列, LLaMA, Claude 擅长: 文本生成, 对话 实际: 足够大时什么都能做

Encoder-Decoder

编码+解码

Encoder: 双向读输入 ↓ (Cross-Attention) Decoder: 单向写输出 代表: T5, BART, 原始Transformer 擅长: 翻译, 摘要 缺点: 架构复杂, 2套参数

为什么 GPT 选择 Decoder-Only？

原因解释
Scaling Law研究证明：同等参数量下，Decoder-Only 的 loss 下降更高效。简单架构 + 大参数 > 复杂架构 + 小参数。
统一范式一切任务都可以表述为"给一段文字，续写下一段"，不需要特殊的编码器。
工程简洁只需一套参数，代码简单，易于分布式训练和优化。
In-Context LearningDecoder 天生擅长利用 prompt 中的示例（few-shot），这在 Encoder 架构中很难实现。

🤔 那 Decoder-Only 不能看后文，理解力会差吗？

实证表明：当模型足够大（>1B 参数），Decoder-Only 的单向注意力通过 Scaling 可以达到媲美 Encoder 双向注意力的理解能力。这就是为什么 GPT-4 不需要 Encoder 也能做文本分类、情感分析等"理解型"任务。

10. MoE 混合专家模型

核心思想：不是所有参数每次都需要

传统"密集模型"每次推理都激活所有参数。MoE 的理念：用路由器选择性地激活少数"专家"，大幅降低计算量。
